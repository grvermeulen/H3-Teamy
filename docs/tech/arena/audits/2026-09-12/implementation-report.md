# GTA H3 — implementation and verification report

For the merged **0.2.3** PR, see the [updated verification record](pr-verification.md).
The measurements and ratings below describe the original implementation on the audit baseline.

Completed locally on 13 September 2026. Baseline: `18cee84`, version `0.2.1`. Verified result: version `0.2.2` on `codex/gta-h3-audit-improvements`, prepared for pull-request review. No deployment or remote migration was performed. See the [original audit](report.md), [implementation plan](implementation-plan.md) and [reproduction instructions](../../../../../e2e/arena/README.md).

The critical multiplayer identity flaw is closed. Rooms, host authority and match completion now have server-enforced boundaries. Network traffic is substantially lower, and the phone layout leaves much more space for the city. This is suitable for a controlled casual-game rollout after applying the migration and checking representative phones. It is still a browser-hosted game with host-reported scores.

## Measured performance

Each district used eight players, the shipped map, 300 warmup ticks and 1,800 measured ticks. These are paired Node **22.23.2** CPU measurements on this Windows machine. The original audit used Node 24, so its timing numbers are not treated as a controlled before/after CPU comparison.

| District   | Host step p95 | Whole-world replay p95 | Local prediction p95 | Snapshot payload reduction |
| ---------- | ------------: | ---------------------: | -------------------: | -------------------------: |
| Rhenen     |      0.745 ms |               0.708 ms |             0.012 ms |                      63.4% |
| Wageningen |      0.828 ms |               0.836 ms |             0.016 ms |                      62.4% |
| Campus     |      0.851 ms |               0.877 ms |             0.008 ms |                      61.8% |
| Bennekom   |      0.834 ms |               0.880 ms |             0.012 ms |                      61.5% |

Payload reduction compares the full encoder with the delta encoder on identical snapshots. It excludes Ably protocol, TLS and fan-out overhead. Full keyframes remain roughly 6.2 KB; typical delta snapshots are 1.8–2.0 KB. Thus the p95 packet size remains close to a full keyframe even though total traffic is much lower.

The five-minute simulation used a host plus seven clients, 10% packet loss and alternating 33–167 ms delivery delay. It maintained exactly 15 Hz active and 2 Hz idle publication per client, a maximum queue of 23 messages, and final idle position errors of 1.2–5.6 cm. The host remained publishing. This proves the exercised loss/delay scenario, not performance of eight physical browsers. See [raw performance results](performance-after.json).

## Remaining risks and next release checks

1. **Host cheating remains possible.** The server verifies who may report a result, the roster, bounds and timing; it does not simulate combat. Results are explicitly labelled host-reported. Before using rankings for prizes or competitive play, move simulation/result adjudication to a trusted game server. This is an architectural follow-up, not a claim that client authority is now cheat-proof.
2. **Validate representative hardware.** Test iOS Safari and an Android phone with a coarse pointer, OS backgrounding, orientation changes and 10–15 minutes of play. Record p95/p99 frames, thermal behavior, memory and touch release after interruptions. The desktop test surface cannot establish these properties.
3. **Budget host migration interruption.** Abrupt disconnection may pause authoritative play until the 12-second lease expires and a heartbeat arrives. Explicitly hidden/disconnected clients can hand over sooner. The round deadline continues on server time.
4. **Raster budgets are soft.** One chunk cannot be interrupted mid-draw and may exceed the target. Cache budgets adapt to a visible working set; extreme resolutions can exceed the nominal 96 MiB ceiling to avoid continual eviction. Verify cold traversal on slower GPUs before raising visual detail.
5. **Deploy the additive migration first.** Existing games must reconnect to the versioned channels. Verify a real two-account production smoke test after deployment. If rollback is necessary, disable multiplayer rather than restore the vulnerable token issuer. No deployment or remote database migration was performed here.

Dependency rationale: the fixes follow the upstream [deepmerge-ts advisory](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), [mysql2 advisory](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr) and [additional mysql2 advisory](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3). Prisma generation, local migration and build checks cover the changed configuration/tooling path; no database backend change was introduced.
